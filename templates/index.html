Why OpenAC

The original game's behavior

Movement, physics, combat, spells and the interface behave as the original client's did. The code is modern; the behavior is the original's.

Windows, Linux and macOS

Native builds for Windows, Linux and Macs with Apple silicon or Intel, drawing through Direct3D 12, Vulkan or Metal.

Plugins in WebAssembly

Plugins are sandboxed, get only the permissions they ask for, and work the same with or without a window.

Many sessions, one program

Run any number of characters at once. Open a window onto any of them and close it again; the session plays on without one.

Play

Up and running in three steps

  1. Download the launcher. It installs the game client and keeps both up to date.
  2. Point it at your game data. OpenAC ships no game data; it uses your own Asheron's Call files.
  3. Pick a server and play. OpenAC connects to ACEmulator servers.
Getting started

Build

Make it yours

  • Write a plugin An ordinary Rust crate built for WebAssembly, against the openac-plugin SDK: set up, test, publish and get listed.
  • Work on the client Build from source with stable Rust, run one session or many, and find your way around.
  • Contribute How changes are made, tested and reviewed.
